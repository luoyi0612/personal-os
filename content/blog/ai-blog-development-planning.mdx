# 一、项目背景

我准备从 0 到 1 搭建一个属于自己的个人 Blog 网站，并尝试使用 AI 全程参与研发。

这个 Blog 不仅仅是一个"写文章的网站"，更像是：

- 我的个人知识库
- AI 工程实验场
- 长期成长记录系统
- 技术与项目管理沉淀平台
- 未来个人品牌的基础设施

整个项目会尽可能采用 AI 协作开发模式，包括：产品设计、信息架构、UI 设计、前端开发、工程化、SEO、部署、内容运营。

最终目标不是"快速做完一个网站"，而是建立一套完整的 **AI Engineering Workflow**。

---

# 二、阶段一：目标定义

## 项目目标

### 技术沉淀

记录前端工程经验、AI 工程实践、项目管理经验、系统设计思考。

### 长期成长

持续输出学习记录、英语学习、AI 使用心得、技术成长路径。

### 建立个人品牌

形成自己的技术方向与内容体系。未来 Blog 可以成为简历资产、面试资产、技术影响力、副业入口、长期知识库。

## 用户定位

- **技术开发者**：前端工程师、AI 开发者、工程化方向开发者
- **技术管理方向**：PM、PMO、技术负责人
- **学习成长型用户**：长期主义学习者、AI 时代转型者

## Blog 核心定位

> AI 时代下的前端工程、项目管理与长期成长

重点输出：AI 协作研发、项目复盘、系统设计、工程思考、长期成长。

---

# 三、阶段二：内容架构设计

整个 Blog 内容体系采用 **知识库 + 项目复盘 + 成长记录** 三层结构。

## 技术知识库

### Frontend Engineering

Vue3、React、TypeScript、微前端、rspack、ECharts、移动端架构、性能优化、工程化。

重点不是"教程"，而是：为什么这么设计、为什么这么拆分、为什么采用这种架构。

### AI Engineering

Claude Code、Cursor Workflow、Prompt Engineering、AI Agent、MCP、RAG、AI 系统设计、AI 开发工作流。

重点：记录真实 AI 协作研发过程。

### Project Management

PRD、需求分析、风险管理、项目推进、跨团队协作、项目复盘、研发流程。

这个方向会成为 Blog 的差异化部分。

### Long-term Growth

英语学习、雅思准备、AI 时代学习方式、技术成长、长期主义、效率系统。

## 项目复盘体系

重点输出真实项目经验，每篇复盘包含：背景、问题、方案、风险、技术实现、结果、复盘总结。

## 成长记录体系

周学习记录、AI 使用心得、踩坑记录、阅读笔记、思考随笔。

---

# 四、阶段三：技术方案设计

## 核心原则：极简 MVP 优先

优先快速上线，再逐步扩展。

## 技术栈

| 层级 | 技术 |
|------|------|
| 框架 | Next.js + React + TypeScript |
| 样式 | TailwindCSS + shadcn/ui + Framer Motion |
| 内容 | MDX（`/content/blog`） |
| SEO | metadata + sitemap + robots + RSS + OG |
| 部署 | Vercel |

选择 Next.js 的原因：SEO 友好、AI 生态成熟、文档丰富、Vercel 部署方便。

---

# 五、阶段四：AI Workflow 设计

整个项目采用 AI 协作开发模式，各阶段分工如下：

| 阶段 | AI 负责 | 人工负责 |
|------|---------|---------|
| 产品 | PRD、信息架构、页面结构 | 判断合理性、确定优先级 |
| UI | 页面风格、组件设计、Design System | 风格统一、品牌调性 |
| 开发 | 页面/组件生成、hooks、SEO、动画 | 架构设计、Code Review |
| 工程 | ESLint、prettier、脚本、测试、文档 | 可维护性把控 |
| 部署 | Vercel 配置、CI/CD、sitemap、RSS | 上线决策 |

---

# 六、阶段五：UI / 品牌设计

## 风格方向

> 极简、技术感、长期阅读友好

避免：花哨动画、复杂装饰、信息过载。

## 视觉原则

- **可读性优先**：大留白、清晰层级、长文阅读舒适
- **技术感**：深色模式、简洁卡片、代码高亮
- **长期主义**：可长期维护、不容易过时、易于扩展

## Design System 需提前定义

字体（标题/正文/代码）、颜色（主色/辅助色/Dark Mode）、spacing、组件规范（Button/Card/Tag/Navbar）。

---

# 七、阶段六：工程规范

## 代码规范

- TypeScript，禁止 `any`
- hooks 独立拆分
- 组件职责单一，不超过 200 行
- 不允许重复逻辑

## 项目目录结构

```
/blog
  /app          # 页面路由
  /components   # 可复用组件
  /content      # MDX 文章
  /hooks        # 自定义 hooks
  /lib          # 工具函数
  /styles       # 全局样式
  /public       # 静态资源
  /types        # 类型定义
```

## 开发阶段规划

**Phase 1 — MVP**：首页、Blog 列表、文章页、About、MDX、SEO、Dark Mode

**Phase 2 — 增强**：搜索、标签系统、RSS、阅读统计、评论

**Phase 3 — 高级**：CMS、AI 搜索、多语言、推荐系统

---

# 八、阶段七：风险预案

| 风险 | 解决方案 |
|------|---------|
| AI 代码失控 | 提前定义架构、小步开发、强制 Code Review |
| 过度设计 | MVP 优先，第一版只实现核心功能 |
| 内容断更 | 建立内容生产流水线（工作问题/学习记录/项目复盘） |
| UI 风格混乱 | 提前建立 Design System 与组件规范 |
| SEO 无流量 | 提前规划关键词、建立内容体系、长期更新 |

# 九、最终目标

这个 Blog 的最终目标不是单纯"搭建一个网站"，而是：

> 建立属于自己的 AI 时代个人能力系统

它会同时成为：技术成长记录、AI 工程实验场、长期知识库、个人品牌平台、项目复盘系统。

未来整个 Blog 的开发过程，也会成为一套完整的 **AI Engineering 实践案例**。
